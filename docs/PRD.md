# 悬赏平台上线版 PRD

> 版本：v1.0
> 状态：实现基线
> 更新日期：2026-09-15

## 1. 第一性原理

平台只解决三件事：发布者安全地托管奖金、接单者明确地交付成果、平台可审计地结算资金。首版保留已经完成且能形成运营闭环的比赛、礼品卡、公告、问答、评价与文件上传，不再引入新的撮合层或抽象。

单人悬赏采用“先到先得”的立即接取模式。不存在报名、候选人筛选或发布者选人流程。

## 2. 角色

- 注册用户：发布悬赏或比赛、接取悬赏、投稿、交付、评价、充值和提现。
- 管理员：审核内容、处理申诉与异常资金、管理用户、公告、礼品卡和运行配置。
- 系统任务：推进逾期状态、释放奖励并执行幂等结算。

所有权限均由服务端校验；被封禁用户只能读取，不可执行写操作。

## 3. 单人悬赏

### 3.1 发布

1. 发布者填写任务说明、验收要求、预算、接取截止时间和接取后的工作时长。
2. 提交时按“充值余额优先、收益余额补足”托管预算。
3. 余额不足时进入 `PENDING_PAYMENT`；余额充足时进入 `PENDING_REVIEW`。
4. 管理员审核通过后进入 `OPEN`；拒绝则按原资金来源退款。

### 3.2 接取与交付

1. 非发布者可在截止前立即接取 `OPEN` 任务。
2. 并发接取只能有一人成功，成功后任务进入 `CLAIMED`。
3. 接单者须在 `dueAt` 前提交文字和文件；每次提交保存一个版本，任务进入 `SUBMITTED`。
4. 发布者可确认、要求一次修改或拒绝。拒绝后接单者可在时限内申诉。
5. 接单超时或拒绝未申诉时，如接取窗口仍开放，任务重新进入 `OPEN`；否则退回托管资金。

### 3.3 奖励

验收通过后任务进入 `COOLING`，奖励冷却 24 小时。管理员可拦截异常奖励；未拦截的奖励由定时任务幂等计入接单者收益余额，任务进入 `COMPLETED`。

## 4. 比赛

- 发布者设置投稿截止时间及一至三个奖项，奖金提交时一次性托管。
- 非发布者可投稿并更新作品版本；发布者可入围、反馈并在截止后选择不同获奖者。
- 奖励经过 24 小时冷却后分别入账；全部奖励完成后比赛进入 `COMPLETED`。
- 公开展示只暴露允许公开的最终作品，私有反馈及历史版本按角色授权。

## 5. 资金

- 充值余额：来自易支付或礼品卡，可用于奖金，不可提现。
- 收益余额：来自完成的悬赏或比赛，可用于奖金，也可提现。
- 提现冻结：提现申请处理中暂时冻结的收益。
- 所有金额使用整数分，费率使用基点；订单保存费率快照。
- 每次余额变化必须经过统一资金服务，并写入带幂等键和余额快照的不可变流水。
- 易支付返回页不入账，只有 `/epay/notify` 的合法异步通知可以入账。
- 提现由管理员发放支付宝红包口令；完成时扣除冻结金额，拒绝或取消时解冻。

## 6. 辅助运营能力

- 公告：管理员发布、置顶并可按用户偏好发送邮件。
- 礼品卡：管理员批量生成、启停，用户一次性兑换到充值余额。
- 问答：任务与比赛均支持公开问答。
- 评价：悬赏完成后，双方基于同一接单记录评价。
- 文件：支持视频和普通附件、分片上传、角色鉴权及历史文件清理。
- 后台：用户封禁、内容审核、奖励拦截、资金调整、充值单处理、提现处理和审计日志。

## 7. 上线验收

- 注册、登录、公开页面和后台页面可正常加载。
- 同一悬赏的并发接取最多一人成功。
- 支付通知重放、奖励任务重跑、礼品卡重复兑换均不会重复入账。
- 余额不足时任何扣款都失败，且业务状态与流水同时回滚。
- 退款准确恢复托管时的充值/收益余额组成。
- 非授权用户无法读取私有说明、交付文件、投稿历史或提现口令。
- 数据库可从唯一初始迁移在空库创建，并能通过生产构建与部署自检。

## 8. 暂不扩展

- 报名、候选人筛选、议价或聊天。
- 多人协作接单、里程碑付款和自动仲裁。
- 自动提现、用户间转账、订阅和复杂财务报表。
- 微服务、消息总线、CQRS 或为未知规模预设的基础设施。
