# 轻量 Web2 悬赏平台 PRD

> 版本：v1.0  
> 状态：范围已确认，待技术基线审计  
> 更新日期：2026-09-07

## 1. 产品概述

基于最新版 Open SaaS 构建一个轻量 Web2 悬赏平台。平台面向所有注册用户开放发布和接单能力，通过易支付完成充值，通过站内受限余额完成悬赏托管和奖金结算。

首版只实现单人悬赏，不实现比赛。平台不自动向接单者分账：奖金完成后进入接单者收益余额，用户集中申请提现，管理员通过支付宝红包口令人工付款。

### 1.1 产品目标

- 让发布者在完成充值后，能够快速发布、审核和托管一笔悬赏。
- 让接单者完成报名、交付、验收和奖金入账的完整闭环。
- 通过累计余额降低管理员逐个任务发送支付宝口令的频率。
- 在快速上线的前提下，保证支付、余额、权限和操作记录可以审计。

### 1.2 首版成功标准

- 新用户可以完成注册、充值、发布悬赏和查看资金流水。
- 接单者可以报名、被选中、提交成果并在验收后获得收益余额。
- 管理员可以审核任务、处理异常、管理充值订单和人工提现。
- 重复支付通知、重复奖金入账和并发提现不会造成资金重复或余额透支。
- 所有重要后台操作均可追溯到管理员、时间、对象和操作结果。

## 2. 用户角色

### 2.1 注册用户

同一个用户可以同时作为发布者和接单者：

- 充值并查看充值状态。
- 发布和管理自己的悬赏。
- 报名其他用户发布的悬赏。
- 提交交付物并查看验收状态。
- 查看充值余额、收益余额和资金流水。
- 使用收益余额申请提现并领取支付宝红包口令。

用户不能报名自己发布的悬赏。

### 2.2 管理员

- 查看和封禁用户。
- 审核、关闭或延长悬赏。
- 查看订单、易支付流水和通知处理记录。
- 查看报名及交付物。
- 拦截异常验收结果或奖金入账。
- 处理人工退款和提现。
- 查看完整操作日志。

所有管理员能力必须在服务端验证管理员权限，不能仅依赖前端隐藏入口。

## 3. 核心业务流程

### 3.1 充值

1. 用户输入希望到账的充值金额。
2. 系统根据当前充值费率计算手续费和实际支付金额。
3. 系统创建易支付订单并跳转收银台。
4. 易支付异步通知通过验签、订单号、金额及状态校验后，充值余额入账。
5. 支付返回页只展示系统内部订单状态，不根据 URL 参数确认支付成功。

充值本金只能用于发布悬赏，不可提现。

### 3.2 发布悬赏

1. 用户填写标题、描述、预算、报名截止时间和交付截止时间。
2. 余额不足时，任务进入 `PENDING_PAYMENT`，页面引导用户充值；充值后由用户重新提交。
3. 余额充足时，系统优先扣减充值余额，不足部分再扣减收益余额，并记录托管资金来源。
4. 任务进入 `PENDING_REVIEW`，等待管理员审核。
5. 管理员通过后进入 `OPEN`；拒绝时退回原资金来源并终止任务。

### 3.3 报名与选人

1. 其他注册用户在报名截止前提交报名说明。
2. 每个用户对同一任务只能保留一条有效报名。
3. 发布者在报名截止前选择一人接单。
4. 选择成功后任务进入 `IN_PROGRESS`，其他报名自动落选。
5. 选人操作必须事务化，确保同一任务只能选中一人。

### 3.4 交付与验收

1. 被选中的接单者在交付截止前提交文字说明和附件。
2. 接单者可以在截止前覆盖更新自己的交付内容，不保留面向用户的版本历史。
3. 提交后任务进入 `JUDGING`。
4. 发布者确认成果后生成等于悬赏预算的待入账奖励。
5. 奖励进入 24 小时冷却期；管理员可以在期间拦截异常结果。
6. 未被拦截的奖励由任务队列自动入账至接单者收益余额，任务进入 `COMPLETED`。

### 3.5 提现

1. 用户从收益余额中申请部分或全部提现。
2. 系统计算提现手续费，展示实际红包金额并冻结申请金额。
3. 管理员在支付宝生成对应金额的红包口令，并录入提现单。
4. 用户在站内查看口令并确认已兑换。
5. 确认后提现完成；拒绝或作废时解冻申请金额。
6. 管理员可以在有审计记录的前提下强制完成提现。

## 4. 余额与手续费规则

### 4.1 余额分类

- **充值余额**：来源于易支付充值，可发布悬赏，不可提现。
- **收益余额**：来源于完成悬赏，可发布悬赏，也可提现。
- **提现冻结金额**：已申请提现但尚未完成或释放的收益。
- **任务托管金额**：已从用户余额扣除并绑定到具体任务的预算。

发布悬赏时优先使用充值余额。任务退款必须按照托管时记录的来源，分别退回充值余额和收益余额。

### 4.2 手续费

管理员可分别配置：

- 充值百分比费率和固定手续费。
- 提现百分比费率和固定手续费。

规则：

- 充值支付金额 = 充值到账金额 + 充值手续费。
- 提现红包金额 = 提现申请金额 - 提现手续费。
- 百分比使用基点存储，金额使用整数分。
- 手续费计算结果向上取整到分。
- 提现红包金额必须大于零。
- 订单和提现单保存费率快照，配置修改不影响历史记录。
- 费率修改必须写入管理员操作日志。

## 5. 页面范围

### 5.1 用户端

- 首页/悬赏列表：标题搜索、状态筛选。
- 悬赏详情：状态、报名、选人、交付和验收操作。
- 发布悬赏：单页表单。
- 我的任务：我的发布、报名和交付。
- 余额中心：充值余额、收益余额、流水、充值和提现。
- 支付结果页。
- 登录与个人资料。

使用 Open SaaS 现有 Shadcn UI，不开发复杂动态流和多层导航。

### 5.2 管理后台

扩展现有 `/admin`：

- 用户查看与封禁。
- 任务审核、延期、关闭和异常处理。
- 充值订单、易支付交易号和通知日志。
- 报名与交付物查看。
- 奖励冷却状态与异常拦截。
- 人工退款记录。
- 提现审核、红包口令录入、作废和强制完成。
- 手续费配置。
- 操作日志。

## 6. 状态定义

任务主流程：

```text
DRAFT → PENDING_PAYMENT → PENDING_REVIEW → OPEN
OPEN → IN_PROGRESS → JUDGING → COMPLETED
```

异常终态：

- `CANCELLED`：未托管资金的草稿或待充值任务被发布者取消。
- `CLOSED`：管理员关闭且不存在待退托管资金的任务。
- `REFUNDED`：已托管任务关闭后，预算已全部退回原余额来源。

任务逾期不自动裁决或退款。系统将其标记为后台待处理事项，由管理员延期、恢复处理或关闭退款。

## 7. 首版不做

- 比赛、多赢家和奖金拆分。
- Stripe 页面、订阅、Webhook 和相关业务。
- 用户间转账、余额赠送和充值本金提现。
- 自动提现、自动分账和自动退款。
- 聊天、评价、排行榜和动态流。
- 复杂纠纷、仲裁和申诉系统。
- 财务统计大屏和复杂运营报表。
- 投稿或交付物的公开展示与版本历史。

## 8. 验收标准

- 只有易支付异步通知验证成功才能增加充值余额。
- 任一业务动作失败时，余额、流水、托管和任务状态必须同时回滚。
- 每笔余额变化都存在对应的不可变流水和业务来源。
- 充值本金无法通过提现接口取出。
- 任务退款能准确恢复充值余额和收益余额的原始组成。
- 奖励、充值和提现均不能因重复请求而执行两次。
- 非任务相关方不能查看报名和交付内容。
- 被封禁用户不能执行任何用户端写操作。
- 管理员操作具有服务端权限校验和审计日志。
