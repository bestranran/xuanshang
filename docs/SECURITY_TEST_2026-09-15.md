## 已修复

### 登录限流可被重置

此前任意成功登录都会清空来源 IP 的失败计数。攻击者可以使用自己的账号穿插成功登录，持续重置同一来源的撞库限制。现在成功登录只清除该邮箱的计数，保留来源 IP 的失败计数。

### 随机账号可造成常驻内存增长

此前每个首次失败的邮箱或 IP 都会写入内存 Map，过期记录只有在同一个键再次出现时才删除。攻击者持续提交随机邮箱可让记录长期增长。现在写入时清理全部过期记录，并把每个限流器限制为最多 50,000 个键；新增了容量和过期回收测试。

### 本地密钥文件权限

`.env.server` 和 `deploy/.env` 当时为 0644。已改为 0600。它们均被 `.gitignore` 排除，历史中也没有被提交；部署脚本本身已使用 `umask 077` 并在创建时设置 0600。

### 浏览器侧基础防护

Caddy 新增禁止页面嵌入的 CSP 和 `X-Frame-Options: DENY`，并禁止未使用的摄像头、麦克风和定位权限，降低点击劫持与无关浏览器能力暴露。

## 未发现被打穿的关键边界

- 支付回调需要有效商户签名，并同时核对订单号、平台交易号、成功状态和精确到分的金额。
- 同一充值订单只能入账一次；交易号和账本幂等键还有数据库唯一约束。
- 钱包扣款使用版本条件更新，余额不足或并发变化会失败，账本和余额更新处于同一事务。
- 任务、比赛、提现、管理操作和文件访问均检查登录身份、管理员身份或资源所有权。
- 礼品卡使用 128 位随机值和 HMAC 存储，并发兑换通过状态条件更新和幂等账本保护。
